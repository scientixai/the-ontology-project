What this is

A ready-made, shared model of how a clinical trial actually runs — from a site’s first activation through an End-of-Phase-2 decision. Instead of every organization re-inventing how to represent studies, subjects, visits, samples, consent and safety data, you inherit a model the industry can share, and your own data plugs into it.

Because it captures who did what, when, and on what evidence — and remembers every version of the truth over time — the documents you already owe (SDTM, USDM, a delegation log, an analysis dataset) come out as views, and a regulator’s question becomes a query.

Reference graph, not a runtime. This is a reference you read, cite, and build your own institutional graph against — the shared model, its constraints, its crosswalks, and worked examples. It is not a system you download and operate: it ships no broker, no pipeline, and no agents.
  • What lives here: the layered ontology (TOP Core → HCLS → CR), graded SHACL constraints, projection definitions, SSSOM crosswalks, and operator worked examples — the grounding.
  • What lives elsewhere: instantiating a real study and serving it as a running NGSI-LD graph is done by a separate engine (the Providence Neural Engine, community edition) — that is what powers the live CDISC demo. This site documents the model that engine consumes; the runtime is out of scope here.

Why bitemporality is hard — a real example

Natural language question

“How is GLP1-TRIAL-27 doing?”

Sounds simple. The reality: 149 participants are simultaneously in different sub-phases of the trial — some still in screening, some mid-treatment, some in follow-up. Twelve sites are at different lifecycle stages (three still activating, one just closed). There are two protocol amendments; a participant’s visit-3 eligibility may have been evaluated under version 1 or version 2 of the protocol depending on when they enrolled. Two SAEs are in the 15-day reporting window.

What the broker answers (NGSI-LD entity query)

GET /ngsi-ld/v1/entities?type=cr:Study&id=urn:ngsi-ld:top-cr:Study:GLP1-TRIAL-27
  &attrs=identifier,status,conductedAt,hasProtocolVersion
  &options=keyValues

What the reasoner adds when the broker returns null or incomplete

The broker holds the runtime state (current entity versions). When a query crosses a temporal boundary — “which protocol version was in effect for Subject 042 at Visit 3?” — the OWL reasoner resolves the bitemporal join. The LLM agent routes: broker first, reasoner on null or temporal qualifier, human escalation on conflict.

The hard truth: answering “how is a trial doing” correctly requires bitemporality (what was true when), concurrent state (149 participants × their individual temporal planes), and provenance (which amendment governed which visit). No flat table gives you all three. This is why the model exists.

The value

Inherit, don't rebuild

Your graph starts with the industry's operator model already in place — the cold-start tax becomes a one-time inheritance.

One model, many views

CDISC SDTM/ADaM, USDM, FHIR, a delegation log, a data mart — all projected from one graph. The standards are views, not the source of truth.

Remembers everything

Every fact carries two clocks — when it was true, and when you knew it. Reconstruct any past state “as of” a date; back-dating is structurally impossible.

Provable by construction

Every assertion records who attested it, when, and on what evidence (W3C PROV) — attestation, not just a citation.

Safe & proportionate

Identifiable data is contained by design; compliance is graded by materiality; monitoring is targeted by risk, not blanket.

Organized by flow

Each sub-domain below is its own page — the screen, the data, the rules, the views — so you read only the part you operate.

Technology tradeoffs — honest

TOP is technology-agnostic. The OWL model is the canonical specification; NGSI-LD is the preferred runtime substrate; LPG / Neo4j is a valid alternative. Each has real tradeoffs.

TOP’s position: the OWL model is the design-time specification and the source of the @context. NGSI-LD is the preferred runtime substrate because bitemporality is native and the standard is broker-agnostic. LPG / Neo4j is a valid implementation choice; the same entity model applies, and this reference graph can serve as the property graph schema. All three benefit from the shared vocabulary; none requires the others.

NGSI-LD and OWL — how they fit together

NGSI-LD is JSON-LD — a serialization of RDF. Every NGSI-LD entity, when expanded, is a valid RDF graph. The TOP CR @context (download) maps the short names used in broker payloads (cr:Study, hasProtocolVersion) to their full IRIs, and annotates ObjectProperty terms with @type: @id so relationship values compact correctly.

What this means in practice:

  • An entity stored in a Scorpio / Orion-LD broker can be loaded into a triple store by expanding its JSON-LD — no conversion required.
  • OWL reasoning over broker data works: load the expanded triples into a reasoner alongside core/v1/shapes.ttl; the class hierarchy and property restrictions apply.
  • SHACL validation works on the same graph: run top-cr-shapes-v1.ttl against the expanded triples to validate any broker payload.
  • The gap: NGSI-LD’s Property-of-Property model (metadata on a Property node) does not map to a single RDF triple; it requires reification. This is the one place where the two models diverge structurally. TOP handles this by using top:observedAt on the entity (transaction time) and top:validFrom / top:validUntil on versioned nodes (valid time), which round-trip cleanly through JSON-LD expansion.

Study & site set-up
Define the study and bring a site from feasibility to first-patient-in — with activation gated on its essential documents, and enrollment that can’t precede activation.Study start-up package
A site is awarded a study and receives a start-up package — not one file, but a set of typed documents (often downloaded one-by-one from a portal). The site's response splits into three work streams — regulatory, budget & contracting, clinical operations — each consuming package documents and producing site-specific outputs (customized ICF, the DoA log, a signed CTA). Regulatory + budget completion gates the SIV and activation.Delegation & attestation
The PI delegates each task to credentialed staff by attestation — and the delegation-of-authority log is a projection of those acts, not a maintained spreadsheet.Recruitment & screening
The funnel from outreach to enrolled participant: campaign → candidate (a site-boundary, PII-side identity) → pre-screening → consented screening with a coded outcome → conversion through the attested Enrollment bridge. Screen failure is an outcome value, never a class.Enrollment & consent
Bind a real person to a pseudonymous study subject (the only legal PII bridge), and obtain consent under a valid delegation.Randomization & blinding
The IxRS/RTSM events as first-class bitemporal facts: the randomization act (subject → arm, under a stratum, with a number), the blinded kit that operationalizes it, and the audited unblinding event — the blind is never silently broken.Drug supply & IMP accountability
The investigational-product custody chain: shipment to site, dispensing to a participant under the blinded kit, return, and authorized destruction — with the drug log as a projection of these events, and a temperature excursion quarantining what it touched.Schedule of Activities
The visit schedule most systems flatten into a 2D table with the timing buried in footnotes — modeled as a timeline: a planned template (windows, relative timing, ordering, repeats), projected onto a participant once the anchor is known, then reconciled against what actually happened.Data capture (EDC) & fidelity
Capture values against variable definitions (CDISC ODM EAV), verify by risk (SDV), and manage queries — with PHI classified at the source.Biospecimen & LIMS custody
Track a specimen’s chain of custody as a bitemporal state machine, its aliquot lineage, and assays — so any result traces back to the blood draw.External lab data transfer (DTA / DTS)
Vendor non-CRF data (safety labs, ECG, imaging, eCOA) arrives under a Data Transfer Agreement / Specification — modeled as a fact graph so vendor terms resolve once, SDTM is a projection, and conformance runs at ingestion.Safety & pharmacovigilance
Adverse events and serious adverse events, with the expedited 15-day reporting clock measured bitemporally (awareness → submission).Risk-based monitoring (RBQM)
Target monitoring by risk: a high-risk critical-to-quality factor must be mitigated; 100% SDV on a low-risk factor is flagged as over-monitoring.Deviations & CAPA
The chain most CR models skip: a critical-to-quality factor is threatened by a latent operational condition (the antecedent — the missing middle), which manifests as a deviation, which triggers a CAPA. Model the cause, not just the event.Pre-IND gate
The front bracket: an IND-enabling narrative where every animal toxicity is addressed by a clinical safety assessment, plus the 30-day review clock.EOP2 & analysis
The back bracket: the analysis traceability spine — native facts → ADaM datasets → Tables/Listings/Figures → endpoint results — and the End-of-Phase-2 decision node that rests on it: a coded go / no-go verdict, evidenced by the outputs, that yields a Phase 3 design. Every table is reproducible-to-source and grounded in the SAP; every result traces to its estimand.Reporting — the CSR
The Clinical Study Report (ICH E3) as a fact graph, not an opaque file: a results section doesn’t just assert a conclusion, it presents the pre-specified table and reports the endpoint result it draws from — each reproducible to its ADaM source. ‘On what does this conclusion rest?’ is a graph walk from the section to the leaf fact.Submission — eCTD
The terminal node: the eCTD submission as a manifest, not a new source of truth. It references the hard-locked database (A1), the Clinical Study Report (A3), the ADaM datasets (A2), and the Define-XML — every arrow points back at already-produced, locked content. This is where TOP-CR ends.Medical coding
The coding workflow the term crosswalks alone don’t carry: a code assignment is a promoted judgment — ‘this verbatim means this MedDRA/WHODrug code’ — with its method (autocoder vs manual), its dictionary version, its coder, and its human review.Site closeout
The site-side of closeout, counterpart of the database lock: the Close-Out Visit, the reconciliations (IMP, device, documents, queries — one act, four scopes), the archived Investigator Site File with its retention clock, and a closure that rests on all of it.Database lock & follow-up
The pivot of closeout: last-patient-last-visit opens the window, the data is cleaned and soft-locked for review then hard-locked for analysis, and after the hard lock nothing changes silently — a late value is only legitimate under a recorded database unlock. Long-term follow-up continues beyond the treatment period.GCP & essential records
The ICH E6(R3) governance vocabulary no existing ontology owns — essential records, source data/documents, audit trail, certified copy, plus the institutional actors — cited to E6(R3), defined descriptively (the obligations live in the shapes, not the classes).TMF document binding
Classify a document to its artifact type (a SKOS scheme aligned to the DIA TMF Reference Model), then bind what its facts mean to the domain class — the comprehension layer the eTMF world omits.Roles, phases & actions
Who can do what, when — the operator-grounding layer that turns the reference graph into a system of record for authorization, delegation, and Jobs to Be Done.Interoperability
Owned, provenance-tagged crosswalks to external ontologies (verified IRIs), and every standard view the graph emits — the standards are projections, not the source of truth.

How to put it to work

1

Ingest a protocol

Parse an ICH M11 / USDM v4 JSON. Map each entity type to its TOP CR equivalent. POST as NGSI-LD entities to your broker with the TOP @context. See the Ingestion worked example for the LY900018 nasal glucagon protocol.

2

Subscribe to a data source

Point the runtime at an S3 bucket (ODM/XML), a Kafka stream (Castor EDC), or a Veeva DDA export. The crosswalk layer maps vendor fields to TOP CR terms; unknown fields route to LLM inference with a confidence score.

3

Validate

Run top-cr-shapes-v1.ttl over the expanded triples. The SHACL contract catches PII leaks, undelegated work, orphan data, premature activation, unmitigated risk.

4

Query across time

Broker queries answer “what is the current state?”. Temporal API queries answer “what was true at T?”. For cross-amendment joins, route to the triple store + reasoner.

5

Emit what you need

Run a projection → SDTM, USDM, FHIR, the DOA log, a data mart, ADaM lineage — provenance intact.

Honest limits

  • Not here: agent orchestration, the runtime/broker — those consume the reference; they aren’t part of it.
  • Pseudonymized, not anonymized: identifiable data is kept from flowing downstream, but statistical anonymization is an upstream/runtime responsibility.
  • Scope today: oncology, Pre-IND → End-of-Phase-2, plus the site-operations layer. The architecture generalizes; the content is bounded.
  • Multi-source provenance: different sponsors run EDC on different platforms (S3/ODM, Databricks, Snowflake, Veeva). The crosswalk layer handles field mapping; but when provenance logs live in different systems, reconciliation is an unsolved problem at the industry level. TOP gives you the vocabulary; the pipeline is implementation work.
