Interoperability

Owned, provenance-tagged crosswalks to external ontologies (verified IRIs), and every standard view the graph emits — the standards are projections, not the source of truth.

cx:MappingCrosswalk MappingEvidenceA curated, provenanced correspondence from a TOP term to an external ontology term.

What it validates

ruleapplies toseverityrequires
cx:MappingShapecx:MappingViolation
  • Mapping justification must be a semapv justification IRI.
  • Mapping must be attributed to an agent (PROV).
  • Mapping must carry a confidence in [0,1].
  • Mapping must carry a mapping date.
  • Mapping must carry a verification status.
  • Mapping must carry transaction time (top:recordedAt).
  • Mapping must name an author/curator (IRI).
  • Mapping must reference a TOP/CR-core subject term (IRI).
  • Mapping must reference the external target term (IRI).
  • Mapping predicate must be a SKOS match predicate.

accountability_log.rqIMP accountability log — the drug log as a PROJECTION of custody events (like the DoA log): every dispensing, return, and destruction on each lot, in valid- time order, with quantities and parties. Reconciliation is arithmetic over this view, never a maintained spreadsheet.
adam_traceability.rqADaM traceability — walk an analysis result to its NATIVE source fact (the lineage leaf). "Reproduce this number" = a prov:wasDerivedFrom+ walk to the fact that has no further source.
analysis_population_membership.rqanalysis_population_membership.rq — Subjects in a named analysis population at the data cut (US-400-004).
certified_copy_register.rqCertified-copy register — each certified copy and the source document it reproduces, with who certified it. The E6(R3) certified-copy chain as a query (an inspector's "show me the original behind this scan" is a lookup, not a hunt).
datamart_itemdata.rqData mart (ExtractionSchema) — flatten the EAV ItemData graph into a tabular view. Demonstrates "the data mart is a projection of the native graph," not a separate store.
deviation_lineage.rqDeviation lineage — trace a CAPA back through the deviation it answers to the latent antecedent and the critical-to-quality factor that antecedent threatened. "Why does this CAPA exist, and what quality factor was ultimately at stake" is a query, not an audit dig.
doa_log.rqDelegation of Authority (DOA) log — PROJECTED from delegation acts. The site-side flagship: the "log" is a query over the graph, never hand-maintained.
dta_data_structure.rqDTA template — Section 7 "Data Structure" table, projected from the model. The handoff's central claim ("the document is a projection; author in the model") made concrete: the template's per-variable columns are rendered from the DataElementSpecification bindings, not authored as prose. Column mapping (template Section 7 → model): Variable ← DataElementSpecification.rdfs:label Controlled Terminology← boundConcept.codedAs (the code URI) — or "UNBOUND" Origin ← cr:elementOrigin (collected | derived) Core ← cr:requirementLevel (required | expected | permissible) (note) ← cr:unboundRationale (why, when unbound) "Bind, don't describe": a bound element renders its code; an explicitly-unbound element renders "UNBOUND" + its rationale — never a silent, ambiguous blank.
dta_document.rqHuman-readable DTA document — rendered from the fact graph, never authored (§7, tier T1/T2). Produces the sponsor-agnostic DTA shell (parties + operational envelope + governing spec) the working group's DTA_Template hand-fills today.
dta_sdtm_lb.rqCDISC SDTM — LB (Laboratory) domain, projected from the native transfer graph. The SDTM target is a VIEW rendered from the concept binding + crosswalk, never a stored authoring target (§7, tier T2: structural automation complete; the study-specific tail — LBTESTCD short-name choice — is an attestation step). Column mapping: DOMAIN = "LB" (literal) USUBJID ← StudySubject.subjectId LBLOINC ← BiomedicalConcept.codedAs (the LOINC anchor; LBTESTCD/LBTEST are rendered from this via the dta-concept crosswalk at projection) LBORRES ← AssayResult rdf:value (original result as delivered) LBORRESU ← DataElementSpecification.declaredUnitConcept (UCUM-canonical unit) VISIT ← the canonical cr:Visit the vendor visit-label resolved to
enrollment_as_of_cut.rqenrollment_as_of_cut.rq — Subjects enrolled as of a named data cut (US-400-003). Uses bitemporal top:validFrom / top:validUntil to filter enrollment valid at cutDate.
entity_actions.rqEntity action registry — the Action layer of the reference entity-view schema (RFC 0001 / ADR-0025). For every authorized-operation archetype in the action catalog (ontology/cr-core-actions.ttl), this returns the target class it operates on, the persona authorized to perform it, and the lifecycle stage it occurs in. A generic entity viewer filters these rows by the entity's class and the operator's role, mapping the entity's current status to a stage (stage-based gating; see ADR-0025). REFERENCE RECIPE, NOT A RUNTIME QUERY. TOP is a reference graph, not a runtime graph: it is the ingredients and recipes, it does not cook the dish. A consumer builds its own customer runtime graph from TOP and drives every rendering decision from that graph, adapting, reweighting, or dropping this projection to fit the customer. TOP does not prescribe it.
fhir_research_subject.rqfhir_research_subject.rq — FHIR R4 ResearchStudy / ResearchSubject projection Expanded (US-500-002): covers Study, Arm, EligibilityCriterion, ResearchSubject with bitemporal validFrom filtering. Usage: sparql --data top-cr-v1.nt --query fhir_research_subject.rq
gdpr_data_map.rqgdpr_data_map.rq — All graph entities transitively linked to a given hcls:Person (US-600-004). Use for GDPR DSAR Art 15 (right of access) — enumerate all personal data held. Substitute ?personIRI with the target person's IRI.

planned_vs_actual.rqPlanned-vs-actual reconciliation — the join a static SoA cannot express. For each realized visit, the planned target and resolved window beside what actually happened, so out-of-window adherence is a projection, not a manual review.
rbqm_monitoring.rqRBQM monitoring allocation — for each critical-to-quality factor, its risk level and the resulting SDV intensity. The risk-targeted monitoring table, projected from the graph.
safety_ae_by_soc.rqsafety_ae_by_soc.rq — Adverse events grouped by MedDRA SOC and PT with subject counts (US-300-005).
safety_dlt_by_cohort.rqsafety_dlt_by_cohort.rq — DLTs per cohort/dose level with CTCAE grade (US-300-005).
safety_susar_dashboard.rqsafety_susar_dashboard.rq — Open SUSARs with deadline and submission status (US-300-005).
sdtm_ae.rqCDISC SDTM — AE (Adverse Events) domain, projected from the native graph. Covers AdverseEvent and its subclasses (e.g. DoseLimitingToxicity) via subclass path.
sdtm_dm.rqCDISC SDTM — DM (Demographics) domain, projected from the native operator graph. One row per enrolled Participant. Standards are views, not the stored model. Column mapping: STUDYID ← Study.studyId (sponsor-assigned; trimmed to 8 chars per SDTM IG convention) DOMAIN = "DM" (literal) USUBJID ← Study.studyId + "-" + Participant.screeningNumber (sponsor-unique concat) SUBJID ← Participant.screeningNumber RFSTDTC ← Participant.enrollmentDate (reference start = first dose or first exposure) RFENDTC ← Participant.completionDate (reference end) RFICDTC ← InformedConsentAct.consentDate (first consent date) BRTHDTC ← Participant.dateOfBirth AGE / AGEU ← derived at projection time (not stored on Participant; avoid redundancy) SEX ← Participant.sex (MALE→M, FEMALE→F, INTERSEX→UNDIFFERENTIATED, UNKNOWN→U) RACE ← Participant.race ETHNIC ← Participant.ethnicity (HISPANIC_OR_LATINO→HISPANIC OR LATINO, etc.) COUNTRY ← Participant.country (ISO 3166-1 alpha-3) SITEID ← Participant.forStudySite identifier (site reference number) ARMCD ← Arm.armCode (assigned arm; null pre-randomization) ACTARMCD ← Arm.armCode (actual arm; matches ARMCD in most trials) INVID ← StudySite.principalInvestigator identifier
sdtm_ds.rqCDISC SDTM — DS (Disposition) domain, projected from Participant lifecycle sub-objects. One row per disposition event (InformedConsentAct, ScreeningRecord, EnrollmentRecord, WithdrawalRecord). Standards are views, not the stored model. Key insight: TOP's sub-object pattern (lifecycle events as first-class records) IS the SDTM DS pattern. Each sub-object maps to exactly one DS row with its DSDECOD controlled term. Column mapping: STUDYID ← Study.studyId DOMAIN = "DS" USUBJID ← Study.studyId + "-" + Participant.screeningNumber DSSEQ ← ordinal (assigned at projection time by event date) DSTERM ← operator-vocabulary reason text DSDECOD ← CDISC CT controlled term (see table below) DSSTDTC ← event date (consentDate / screeningStartDate / enrollmentDate / withdrawalDate) DSCAT ← category (PROTOCOL MILESTONE / STUDY COMPLETION STATUS) DSDECOD mapping: InformedConsentAct (consentStatus=OBTAINED) → INFORMED CONSENT OBTAINED InformedConsentAct (consentStatus=RECONSENTED) → RECONSENTED InformedConsentAct (consentStatus=WITHDRAWN) → WITHDRAWAL OF CONSENT ScreeningRecord (screeningOutcome=SCREEN_FAILED) → SCREEN FAILURE ScreeningRecord (screeningOutcome=ENROLLED) → ENROLLED EnrollmentRecord → ENROLLED WithdrawalRecord (withdrawalCategory=CONSENT_WITHDRAWN) → WITHDRAWAL OF CONSENT WithdrawalRecord (withdrawalCategory=INVESTIGATOR_DECISION) → DISCONTINUED WithdrawalRecord (withdrawalCategory=AE) → ADVERSE EVENT WithdrawalRecord (withdrawalCategory=LOST) → LOST TO FOLLOW-UP WithdrawalRecord (withdrawalCategory=COMPLETED) → COMPLETED
sdtm_ex.rqCDISC SDTM — EX (Exposure) domain, projected from dosing acts (cr:Administration).
sdtm_sv.rqCDISC SDTM — SV (Subject Visits) domain, projected from VisitOccurrence. One row per subject per visit. Standards are views, not the stored model. Column mapping: STUDYID ← Study.studyId DOMAIN = "SV" USUBJID ← Study.studyId + "-" + Participant.screeningNumber VISITNUM ← VisitDefinition.visitNumber (absent for unscheduled) VISIT ← VisitDefinition.visitName / "UNSCHEDULED" for unscheduled VISITDY ← VisitDefinition.plannedStudyDay (protocol-defined) SVSTDTC ← VisitOccurrence.actualStartDate SVENDTC ← VisitOccurrence.actualEndDate SVUPDES ← VisitOccurrence.unscheduledReason (unscheduled visits only)

tmf_binding_map.rqTMF binding map — for each TMF artifact type, the domain class its facts are bound to. Once a system has classified a document to its artifact type, this tells it which ontology entities to expect inside. The comprehension layer the eTMF world omits, as a query.
tmf_completeness.rqTMF completeness / inspection-readiness report — the expected-vs-filed diff as a query. For each artifact type the TMF's profile expects, is a CURRENT filed artifact present? essentiality distinguishes an inspection finding (essential GAP) from a reviewable gap. This is the manual TMF audit, run as one query over the onboarded graph.
